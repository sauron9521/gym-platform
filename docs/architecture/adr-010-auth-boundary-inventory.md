## Actual HTTP operations and proposed ownership

All five legacy Auth controllers are still registered in AuthModule. The tracked canonical OpenAPI document and the controller registry spec enumerate the same 17 operations. Audience is ownership, not an authorization grant. In particular, Admin includes unauthenticated entrypoints with explicit credential/origin checks, and the existing email controller is mixed.

All operations retain AuthNoStoreInterceptor and the early AuthNoStoreMiddleware. IP budgets below are requests per minute: the global default is 10, and method-level overrides are shown. Success codes are from the canonical artifact; existing error contracts and validation are also preserved.

Its tags for Auth are Authentication, PasswordReset, EmailVerification, Tokens and Sessions. ## Compatibility hazards before any route move

1. **Operation IDs and tags.** [OpenAPI factory](../../apps/api/src/infra/openapi/openapi.ts) derives IDs as controller + underscore + method. Swagger default tags also derive from the controller. Splitting mixed controllers can change both even with identical URL and payload. Explicitly preserve every old operationId and tag; keep IDs unique. Existing client type and email-flow tests reference these identifiers.
2. **Rate-limit identity.** The installed locked @nestjs/throttler default generateKey hashes class name, handler name, throttler name and tracker. Renaming a class or handler changes the IP counter key, even when the same decorator budget remains. Preserve stable legacy key identity for moved/split handlers or require a separately reviewed migration decision. Verify continuity with seeded counters, not only decorator metadata. The secondary account HMAC namespaces are separate and must also remain unchanged.
3. **Historical inventory and imports.** The frozen migration inventory includes all five controller paths, their controller barrel index.ts and historical tests. Current validated source relocation map supports same-feature/same-filename controller and test moves only. The barrel and splitting one controller into multiple classes require an explicit reviewed compatibility strategy; do not delete the original inventory record or relax validation broadly. Existing Auth E2E tests import via the legacy controller barrel; endpoint-policies.spec.ts imports AuthController directly. Update these consumers and the live docs with each move. Avoid a legacy re-export that violates inward-import rules.
4. **Session ownership.** Current Admin-specific revoke-all is a transaction locking the active owner, deleting only rows with metadata purpose admin, then clearing Admin cookie. Keep both steps, including clearing after prior revocation. Do not infer that the ordinary sign-out-everywhere or session-list behavior has a new purpose filter; preserve actual package/store semantics.
5. **MFA scope.** Ordinary cookie __Host-sid and Admin cookie __Host-admin-sid are distinct. Admin absolute 8 hours / idle 15 minutes and Admin-only trusted origin remain. Transitional password-only Admin sessions with undefined MFA are currently supported; pending and unknown states fail closed for privileged reads; verified principals require TOTP assurance and current role. Recovery grants do not authorize existing Admin routes. Do not add mandatory enrollment or change status/error semantics in this migration.

### ABI05b1 compatibility mechanism

Use the method-level [StableHttpOperation decorator](../../apps/api/src/common/http/stable-http-operation.decorator.ts) on all 17 Auth operations. Its literal legacy controller and handler names determine the published operation ID and the existing default-throttler SHA-256 key; the explicit tag preserves the previous Swagger grouping. Pass the same endpoint budget when replacing an existing throttle override, or omit it to inherit the global default. Do not stack it with another method-level RateLimit or Throttle decorator: Nest writes the same metadata keys. The global guard, tracker, Redis hashing and secondary account HMAC quotas are unchanged.

Keep the legacy literals when moving or renaming a handler. The Auth controller registry pins every key identity; the real OpenAPI E2E pins all 17 route/ID/tag/status tuples. The Redis HTTP regression exercises an existing stock Nest counter across a renamed class and handler, including independent tracker and route buckets. These tests and canonical regeneration remain mandatory for later slices. No new routes or auth semantics are introduced.

## Delivery recommendation

- ABI05b1: preserve exact operation-ID/tag and rate-limit identity contracts in tests; design the minimal compatibility mechanism before splitting methods. No route move in this slice.
- ABI05b2: introduce a narrow Admin session operation instead of direct PrismaSessionStore access in SessionsController; preserve transaction, cookie and status behavior. Keep internal stores private.
- ABI05b3: expose narrow credential/guard/schema/interceptor contracts where needed, without registering duplicate providers. Decide placement of transport guards and middleware; preserve allowed cross-feature actor contracts.
- ABI05c: move PasswordResetController and TokensController independently, retaining class/method names. Update registry, historical relocations, docs and imports in each PR.
- ABI05d: split mixed email, login and session controllers one bounded slice at a time. Preserve explicit legacy operation IDs, tags and throttle key identity, public pending-MFA logout exceptions and existing security metadata. Resolve the legacy barrel/inventory before removal.
- ABI05e: complete controller-free AuthModule, verify real DI/registry composition and full Auth/Admin regression matrix. Review merged evidence before ABI06.

Do not combine this plan with mandatory MFA enrollment, RBAC redesign, new infrastructure or separate deployable processes. Each runtime slice needs current-main review and green checks before manual merge.
