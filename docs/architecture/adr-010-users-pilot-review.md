### Preserved route ownership

| Audience | Owner                | Routes                                                                                                                                                                                                           |
| -------- | -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Admin    | AdminUsersApiModule  | GET /admin/users, GET /admin/users/:userId                                                                                                                                                                       |
| Shared   | SharedUsersApiModule | GET /users/me/capabilities; GET and PATCH /users/me; PATCH /users/me/preferences; GET and PATCH /users/me/preferences/workouts; POST /users/me/preferences/workouts/initialize; POST and DELETE /users/me/avatar |
| Public   | PublicUsersApiModule | GET /avatars/:key                                                                                                                                                                                                |

The public route continues serving only validated current avatars through AvatarPublicReadFacade. The shared upload/delete adapter uses AvatarSelfFacade and the authenticated account ID. Admin read keeps its cookie-only provider, origin/purpose guards, post-auth read permission guard and allowed-read audit. AdminUsersReadService also checks the operator permission before persistence; it relies on an authenticated actor supplied by its caller, not independently authenticated credentials. Current AdminSessionAuth reloads the active user; its verified MFA principal requires TOTP assurance and current Admin role. The existing transitional password-only Admin session with undefined MFA remains supported; the pilot neither mandates MFA enrollment nor changes this policy.

## Remaining risks and follow-up ownership

| Priority | Finding                                                                                                                                                                                                                                            | Required handling                                                                                                                                                                                                                                                |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1       | Auth mixed controllers and generated client operation IDs. Current Swagger factory derives IDs from controller and method names. Moving individual methods to a differently named class can silently change client types even with identical URLs. | ABI05: establish exact operation ID compatibility tests or explicit overrides before splitting; preserve canonical semantic equality.                                                                                                                            |
| P1       | Auth providers and stores self-register in authentication/storage registries; token cleanup is scheduled. Duplicating providers in audience modules can change registry order, session routing or cleanup ownership.                               | ABI05: keep provider/store registration in AuthModule, prove singleton ownership and expected registration order in real composition; do not re-bootstrap AuthenticationModule.                                                                                  |
| P1       | Admin session semantics include transitional undefined MFA, TOTP/recovery scope, 15-minute idle and 8-hour absolute TTL, and purpose-specific revocation.                                                                                          | ABI05: preserve current behavior, negative authorization and transaction tests. Security changes require their own approval.                                                                                                                                     |
| P2       | Users public-api currently combines pure policy exports and injected runtime services; legacy consumers still import allowed exported services directly. UsersService also exposes transaction-aware methods.                                      | Coordinate [#918](https://github.com/sauron9521/gym-platform/issues/918) and [#919](https://github.com/sauron9521/gym-platform/issues/919) for explicit pure versus injected contracts and incremental narrower boundaries. Do not duplicate that work in ABI05. |
| P2       | Static architecture checks enforce source imports and literal controller registrations, not arbitrary dynamic DI reachability or method-level permission semantics.                                                                                | Retain runtime registry and HTTP negative tests per slice; coordinate inner-layer guard evolution with [#920](https://github.com/sauron9521/gym-platform/issues/920).                                                                                            |
| P2       | Physical file moves broke a Markdown link in ABI04b and historical inventory validation locally in ABI04c.                                                                                                                                         | Update live documentation and validated source relocations in the same PR, preserve the frozen inventory, run all root tooling before push.                                                                                                                      |
| Later    | Single-process cleanup ownership is not multi-replica coordination or fault isolation.                                                                                                                                                             | Track multi-instance/filesystem concerns in #918 and production strategy; no worker or separate Admin deployment in this ADR.                                                                                                                                    |

## ABI05 proposed sequence

1. ABI05a — pin current Auth dependency and operation inventory, including ordinary and admin session flows, AuthNoStore middleware/interceptor, rate-limit guards, authentication registry and storage source registration. Record operation ID preservation and negative test matrix before moving any route.
2. ABI05b — prepare narrow injected auth contracts for session operations and credentials; keep PrismaSessionStore and token/MFA stores private. Separate transport-facing methods from persistence without changing session policies, cookie side effects or authentication package registration.
3. ABI05c — migrate complete, low-coupling public credential/recovery controllers individually where audience classification is unambiguous. Verification resend is authenticated despite its existing mixed email controller; do not classify all email endpoints as public.
4. ABI05d — separate mixed AuthController and SessionsController methods in reviewed slices, preserving old paths, statuses, tags and operation IDs. Admin login and pending-MFA admin logout are deliberately unauthenticated transport entrypoints owned by the admin audience; preserve origin guard. Ordinary sign-out also retains its pending-MFA public exception. Keep ordinary and admin cookies, revocation and no-store behavior distinct.
5. ABI05e — complete controller-free AuthModule only when every route has an owner and runtime DI/registry tests pass. Run canonical schema/client parity, API principal isolation, auth-session-management, admin MFA enrollment/challenge/recovery, token/session store contracts, recovery throttling, no-store and browser admin-cookie regressions. Review merged evidence before ABI06.

Re-pin main and reconcile open security/MFA work before each slice. No broad rewrite, new dependency, new auth provider or role change is authorized. The proposed sequence is a planning recommendation; owner approval of limited rollout remains separate from pilot PASS and merging this record.
